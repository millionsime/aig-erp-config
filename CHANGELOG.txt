4. WORKFLOWS  (2 active)

--------------------------------------------------------------------------------
4a. WORKFLOW "AIG Procurement Approval"  (DocType: Purchase Order)
--------------------------------------------------------------------------------
CREATE  Workflow  AIG Procurement Approval  (is_active = 1)
  Workflow States (7):
    Draft                              (docstatus 0)
    Pending Purchase Committee Approval(docstatus 1, allow_edit: Purchase Committee)
    Pending Enterprise Head Approval   (docstatus 1, allow_edit: Enterprise Head)
    Pending Corporate Approval         (docstatus 1, allow_edit: Corporate)
    Pending CEO Approval               (docstatus 1, allow_edit: CEO)
    Approved                           (docstatus 1)
    Rejected                           (docstatus 2)
  Transitions (11) enforce the tiered policy with NO path that skips a gate:
    Draft -> Submit for Direct Purchase  -> Approved        (< ETB 20,000)
    Draft -> Submit for Committee Review -> Pending Purchase Committee Approval
                                            (ETB 20,000 - 750,000, Proforma)
    Pending Purchase Committee Approval -> Approve -> Pending Enterprise Head Approval
    Pending Enterprise Head Approval    -> Approve -> Pending Corporate Approval
    Pending Corporate Approval          -> Approve -> Pending CEO Approval
    Pending CEO Approval                -> Approve -> Approved
    (Bulky / Open Tender > ETB 750,000 follows the committee + head + corporate
     + CEO chain as above.)
    Any pending state -> Reject -> Rejected
  KEY POLICY FIX: the Enterprise Head approval is a MANDATORY, non-skippable
  workflow state on the Proforma tier. Verified by acceptance test T2 (no
  transition reaches Approved without passing Pending Enterprise Head Approval,
  and a head from another enterprise cannot approve).
  v16 CONSTRAINT: Draft(docstatus 0) -> Rejected(docstatus 2) is forbidden by
  the engine, so the Purchase Order is SUBMITTED (docstatus 1) when it enters
  committee review; pending states therefore carry docstatus 1.

6. SERVER SCRIPTS  (4)  -- *** FLAGGED, as required by the brief ***
================================================================================
Each runs in the Frappe RestrictedPython sandbox (no core edits).
FLAG  Server Script  "AIG - Payment Three-Way Match"
        Type: DocType Event, Payment Entry, Before Submit.
        Reason: enforce PO -> Purchase Receipt (Model 19) -> Purchase Invoice ->
        Payment linkage before a payment can be submitted (three-way match).
        Logic is PI-centric (v3): validates the paid amount against the Purchase
        Invoice allocation and derives the linked PO + submitted Purchase Receipt
        from the invoice lines. Uses tolerance tol(x)=max(10, 0.5%).
FLAG  Server Script  "AIG - PO Cost Center Default"
        Type: DocType Event, Purchase Order, Before Validate/Insert.
        Reason: default the custom aig_cost_center field on new Purchase Orders.
FLAG  Server Script  "AIG - PO Guard Raw Submit"
        Type: DocType Event, Purchase Order, Before Submit.
        Reason: block a raw submit that bypasses the workflow (throws when
        workflow_state == "Draft"), so the approval chain cannot be skipped.
FLAG  Server Script  "AIG - PE Guard Raw Submit"
        Type: DocType Event, Payment Entry, Before Submit.
        Reason: same guard for Payment Entry raw submits.

ADDENDUM 2 - REHEARSAL BUG FIXES (permission + server-script regression)
================================================================================
UPDATE  Server Script "AIG - Payment Three-Way Match" REDEPLOYED as v3
        (PI-centric, RestrictedPython-safe). The live record had regressed to the
        old v2 which used the illegal name "_tol" and required a PO reference,
        crashing Payment Entry submit with a SyntaxError. Verified: compiles under
        RestrictedPython; demo payment reconciles (PI -> PO -> Model 19 receipt).
CREATE  Custom DocPerm  Account / permlevel 0 / read=1 for AIG Deputy, AIG CEO,
        AIG Enterprise Head, AIG Purchase Committee, AIG Evaluation Committee.
        Reason: opening a Payment Entry or Purchase Invoice form calls
        erpnext.accounts.party.get_party_account(), which throws PermissionError
        ("User don't have permissions to select/read this account") unless the
        role can read the party Account. Corporate/Finance/Procurement Officer
        already had it. Verified for finance, deputy, corporate, ceo, committee1,
        head.agro. Also updated source script 05_permfix.py so a rebuild is correct.
DELETE  195 orphaned Custom DocPerm rows (parent NULL) left by the earlier
        dt->parent field-rename bug; these were engine-invisible clutter.
